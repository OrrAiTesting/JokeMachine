# MILESTONES – מכונת הבדיחות

מסמך זה מגדיר את אבני הדרך לפיתוח המוצר. הוא מתבסס על:
- [PRD.md](PRD.md): דרישות המוצר.
- [ARCHITECTURE.md](ARCHITECTURE.md): הארכיטקטורה הטכנית.
- [DESIGN.md](DESIGN.md): העיצוב.

לפי ARCHITECTURE.md אין במוצר מסד נתונים, ולכן אין Database Migrations ואין סביבות Database נפרדות. ההפרדה בין Development ל-Production היא רק ברמת משתני הסביבה (API Keys נפרדים).

## Development Execution Rules – כללי ביצוע הפיתוח

> **הנחיה מחייבת ל-AI שמבצע את הפיתוח:**
> 1. יש לפתח את ה-Milestones **לפי הסדר** שמוגדר במסמך זה.
> 2. בסיום כל Milestone יש **לעצור** ולהציג למשתמש:
>    - את התוצר שהושלם.
>    - קישור לבדיקה (Preview או Production), אם יש.
>    - את תוצאות הבדיקה של **כל** סעיף ב-Definition of Done. סעיף שנכשל או לא נבדק יסומן במפורש.
> 3. **אסור להתחיל את ה-Milestone הבא בלי אישור מפורש מהמשתמש.**
> 4. המשתמש אינו מתכנת. כל פעולה שהוא צריך לבצע בעצמו (יצירת חשבון, העתקת מפתח, הגדרה בממשק של שירות חיצוני) תוצג כהדרכה צעד אחר צעד, בשפה פשוטה.
> 5. אין להוסיף פיצ'רים, מסכים או התנהגויות שלא מופיעים ב-PRD, ב-ARCHITECTURE.md או ב-DESIGN.md.
> 6. ה-API Key לא נכתב לקוד, לא נכנס ל-Git ולא מוצג בתשובות. מפתח שהמשתמש מדביק בשיחה נשמר רק בקובץ `.env.local`.

## Milestone 1 – הקמת הפרויקט והפריסה האוטומטית

**מטרה:** להקים את הבסיס הטכני ואת שרשרת הפריסה, כך שכל שינוי בקוד יגיע לאוויר אוטומטית. זה תנאי מקדים לכל שאר השלבים.

**מה יש לממש:**
- פרויקט Next.js 16 (App Router) עם TypeScript ו-Tailwind CSS 4.
- מעטפת האפליקציה:
  - `<html lang="he" dir="rtl">`.
  - טעינת הגופנים Heebo ו-Frank Ruhl Libre דרך `next/font`.
  - Metadata בסיסי עם הכותרת "מכונת הבדיחות".
- הגדרת צבעי ה-Style Guide כ-Design Tokens של Tailwind (לפי DESIGN.md, סעיף 2.1).
- דף ראשי זמני שמציג את הכותרת **מכונת הבדיחות** בלבד.
- `.gitignore` שכולל את `.env*.local`, וקובץ `.env.example` עם שמות המשתנים `ANTHROPIC_API_KEY` ו-`ANTHROPIC_MODEL`, בלי ערכים.
- Security Headers ב-`next.config.ts`, לפי ARCHITECTURE.md (סעיף 2.10).
- **פעולות של המשתמש, בהדרכה צעד אחר צעד:**
  1. יצירת Repository ב-GitHub והעלאת הקוד.
  2. יצירת חשבון Vercel, חיבור ה-Repository והגדרת `main` כענף ה-Production.
  3. יצירת חשבון ב-Anthropic Console והפקת שני API Keys: אחד ל-Development ואחד ל-Production.
  4. הגדרת Spend Limit חודשי בחשבון Anthropic.
  5. הגדרת משתני הסביבה:
     - מפתח ה-Development נשמר ב-`.env.local` במחשב, וגם ב-Vercel עבור סביבת Preview.
     - מפתח ה-Production נשמר רק ב-Vercel עבור סביבת Production.
     - שני המפתחות מסומנים ב-Vercel כ-Sensitive.

**תוצר מצופה:** אתר שמציג את הכותרת בעברית, רץ מקומית (`npm run dev`) ופרוס ב-Vercel. כל Push ל-GitHub יוצר פריסה אוטומטית.

**Definition of Done:**
- [ ] `npm run dev` מציג מקומית את הכותרת **מכונת הבדיחות**, מימין לשמאל ובגופן Frank Ruhl Libre.
- [ ] `npm run build` עובר בלי שגיאות.
- [ ] Push לענף שאינו `main` יוצר Preview Deployment עם כתובת ייחודית שעובדת.
- [ ] Merge או Push ל-`main` מעדכן את כתובת ה-Production אוטומטית.
- [ ] `.env.local` לא נמצא ב-Repository, ו-`.env.example` קיים בלי ערכים.
- [ ] משתני הסביבה מוגדרים ב-Vercel עבור Preview ועבור Production, ו-Spend Limit מוגדר ב-Anthropic. המשתמש מאשר זאת.
- [ ] ה-Security Headers מופיעים בתשובת ה-HTTP של האתר הפרוס.

## Milestone 2 – קבלת בדיחה מקצה לקצה

**מטרה:** לממש את היכולת המרכזית של המוצר. המשתמש מקליד נושא, או משאיר את התיבה ריקה, ומקבל בדיחה מה-AI, במסך המעוצב לפי ה-Mockup.

**מה יש לממש:**
- **Backend:**
  - `POST /api/joke`, לפי חוזה ה-API ב-ARCHITECTURE.md (סעיף 2.6): ולידציה, `trim()` ותשובה בפורמט `{ joke }`.
  - מודול `joke-service` (server-only), לפי ARCHITECTURE.md (סעיף 2.5):
    - System Prompt: קהל 18+, הומור לא פוגעני, בדיחה אחת, בשפת הנושא, טקסט בלבד.
    - הנושא נשלח בתוך התגית `<topic>`. כשאין נושא, נשלחת בקשה לבדיחה כללית בעברית.
    - הפרמטרים: `model` (מתוך משתנה סביבה), `effort: "low"`, `max_tokens`, `fallbacks`.
    - חילוץ הטקסט מהתשובה.
  - Route Handler עם `dynamic = "force-dynamic"` ו-`maxDuration`.
- **Frontend: המסך הראשי לפי DESIGN.md (סעיף 1.1) ו-`mockups.png`:**
  - רקע הזרקור וקשתות הזהב.
  - הסמל (Emblem), הכותרת בסגנון Display, תיבת טקסט בסגנון Lozenge עם מצב Focus, וכפתור ראשי בזהב.
  - Card · Joke שמוצג אחרי קבלת בדיחה, עם `dir="auto"` ו-`white-space: pre-line`.
  - שליחה בלחיצה על הכפתור או על Enter.
  - מצב טעינה: הכפתור בסגנון Loading / Disabled עם הטקסט **חושב על משהו מצחיק...**, והוא חסום ללחיצה.
  - הנושא נשאר בתיבה אחרי קבלת תשובה. בדיחה חדשה מחליפה את הקודמת.
  - נגישות: `label` לתיבה, `aria-live` לאזור התוצאה, `aria-busy` בזמן טעינה.
  - טקסטי הממשק מרוכזים ב-`lib/messages.ts`.

**תוצר מצופה:** ב-Preview Deployment, משתמש יכול לקבל בדיחות על נושאים שונים ובדיחות כלליות, במסך שנראה כמו ה-Mockup.

**Definition of Done:**
- [ ] הנושא "חתולים" מחזיר בדיחה בעברית על חתולים.
- [ ] תיבה ריקה, או תיבה עם רווחים בלבד, מחזירה בדיחה כללית בעברית.
- [ ] הנושא "cats" מחזיר בדיחה באנגלית, שמוצגת משמאל לימין.
- [ ] לחיצה חוזרת עם אותו נושא מחזירה בדיחה חדשה, שמחליפה את הקודמת, והנושא נשאר בתיבה.
- [ ] Enter במקלדת שולח את הבקשה.
- [ ] בזמן טעינה מוצג **חושב על משהו מצחיק...**, ולחיצות נוספות לא שולחות בקשות נוספות (נבדק בלשונית Network).
- [ ] המסך תואם ל-`mockups.png` ול-DESIGN.md ברוחב מובייל של 375px: צבעים, גופנים, צורות Lozenge, כרטיס, זוהר ו-RTL.
- [ ] ה-API Key לא מופיע בקוד שנשלח לדפדפן. חיפוש של `sk-ant` בקבצי ה-JS שהדפדפן טוען לא מחזיר תוצאות, ו-`npm run build` עובר עם `server-only`.
- [ ] הבדיקות בוצעו על Preview Deployment, ולא רק מקומית.

## Milestone 3 – טיפול בשגיאות ובמקרי קצה

**מטרה:** להבטיח שהמשתמש תמיד מבין מה קרה, גם כשאין חיבור או כשמשהו נכשל. זה מממש את Flow 3 ואת טבלת מקרי הקצה ב-PRD.

**מה יש לממש:**
- **Backend:**
  - מיפוי שגיאות לפי ARCHITECTURE.md (סעיף 2.6): `400 invalid_request`, `502 ai_error`, `502 empty_response`, `500 server_error`.
  - הגדרות ה-Client של Anthropic: `timeout` של 25 שניות ו-`maxRetries: 1`.
  - Log בצד השרת שכולל רק את סוג השגיאה והסטטוס, בלי תוכן הנושא או הבדיחה ובלי המפתח.
- **Frontend:**
  - בדיקת `navigator.onLine` לפני השליחה, וזיהוי כשל רשת ב-`fetch`. בשני המקרים מוצג **אין חיבור לאינטרנט. בדקו את החיבור ונסו שוב.**
  - `AbortController` עם 30 שניות. בחריגה, ובכל תשובה שאינה `200`, מוצג **אופס, משהו השתבש. נסו שוב.**
  - הצגת ההודעות ב-Card · Message עם אייקון ההתראה, לפי DESIGN.md.
  - אחרי שגיאה, הכפתור חוזר להיות פעיל.

**תוצר מצופה:** כל מקרי השגיאה והקצה שמוגדרים ב-PRD מטופלים בהודעה המתאימה, והמשתמש יכול לנסות שוב.

**Definition of Done:**
- [ ] במצב Offline (DevTools או מצב טיסה), לחיצה על הכפתור מציגה את הודעת "אין חיבור" ב-Card · Message, בלי לשלוח בקשה.
- [ ] כשה-API Key שגוי או חסר (נבדק מקומית), מוצגת **אופס, משהו השתבש. נסו שוב.**, ובתשובת ה-API אין פרטים פנימיים.
- [ ] Timeout מדומה (מקומית) מציג את ההודעה הכללית אחרי 30 שניות לכל היותר.
- [ ] בקשה עם גוף לא תקין מחזירה `400 { "error": "invalid_request" }`.
- [ ] נושא ארוך מאוד (למשל 2,000 תווים) נשלח ומטופל בלי קריסה.
- [ ] אחרי כל שגיאה, הכפתור פעיל, וניסיון חוזר מצליח כשהתקלה נפתרה.
- [ ] ב-Vercel Logs לא מופיעים נושאים, בדיחות או המפתח.
- [ ] כל בדיקות ה-Definition of Done של Milestone 2 עדיין עוברות.

## Milestone 4 – התקנה כ-PWA ופתיחה ללא חיבור

**מטרה:** לאפשר להתקין את האפליקציה במסך הבית ולפתוח אותה גם בלי חיבור לאינטרנט, לפי Flow 4 ו-FR5 ב-PRD.

**מה יש לממש:**
- `app/manifest.ts`:
  - `name` ו-`short_name`: "מכונת הבדיחות".
  - `display: "standalone"`, `start_url: "/"`, `lang: "he"`, `dir: "rtl"`.
  - `theme_color` ו-`background_color` מצבעי ה-Style Guide.
- אייקונים בסגנון ה-Emblem של DESIGN.md: 192×192, 512×512, גרסת `maskable` ו-`apple-touch-icon` (180×180).
- `public/sw.js`, לפי ARCHITECTURE.md (סעיף 2.9):
  - Network-first לניווט.
  - Cache-first לנכסים סטטיים.
  - בלי Cache ובלי יירוט של בקשות `/api/*`.
  - ניקוי Caches של גרסאות קודמות.
- רישום ה-Service Worker ב-Production בלבד, ו-Header `Cache-Control: no-cache` לקובץ `sw.js`.

**תוצר מצופה:** אפשר להתקין את האפליקציה ב-Android וב-iOS. היא נפתחת במסך מלא עם השם והאייקון, ונטענת גם בלי חיבור.

**Definition of Done:**
- [ ] בלשונית Application ב-Chrome DevTools, ה-Manifest תקין ומוצג כ-installable, בלי שגיאות.
- [ ] ב-Android (Chrome) אפשר להתקין את האפליקציה מה-Preview, והיא נפתחת במסך מלא בלי ממשק הדפדפן, עם השם **מכונת הבדיחות** והאייקון.
- [ ] ב-iOS (Safari), "הוספה למסך הבית" יוצרת אייקון, והאפליקציה נפתחת במסך מלא.
- [ ] אחרי פתיחה ראשונה עם חיבור, במצב טיסה: האפליקציה נפתחת עם העיצוב המלא (גופנים, צבעים), ולחיצה על הכפתור מציגה את הודעת "אין חיבור".
- [ ] בקשות `/api/joke` לא נשמרות ב-Cache Storage, וכל לחיצה עם חיבור מחזירה בדיחה חדשה.
- [ ] אחרי פריסה של גרסה חדשה, האפליקציה המותקנת מציגה את הגרסה החדשה בפתיחה הבאה עם חיבור.
- [ ] כל בדיקות ה-Definition of Done של Milestones 2 ו-3 עדיין עוברות.

## Milestone 5 – השקה ל-Production ובדיקות קבלה

**מטרה:** לפרסם את המוצר המלא בכתובת ה-Production ולוודא שהוא עומד בכל הדרישות בסביבה האמיתית ובמכשירים אמיתיים.

**מה יש לממש:**
- Merge של כל העבודה לענף `main`, שמפעיל פריסה אוטומטית ל-Production.
- וידוא שסביבת ה-Production משתמשת במפתח ה-Production, ושה-Spend Limit פעיל.
- מעבר על כל דרישות ה-PRD מול הגרסה החיה.
- תיקון ליקויים שנמצאו, בלי להוסיף יכולות חדשות.

**תוצר מצופה:** "מכונת הבדיחות" זמינה לציבור בכתובת ה-Production, ניתנת להתקנה ועומדת בכל הדרישות.

**Definition of Done:**
- [ ] כתובת ה-Production נטענת ב-HTTPS ומציגה את המסך המעוצב.
- [ ] כל User Stories ב-PRD (סעיף 2.ב) עברו בדיקה ידנית על כתובת ה-Production.
- [ ] כל השורות בטבלת מקרי הקצה ב-PRD (סעיף 4.ב) נבדקו, והתוצאות מוצגות למשתמש.
- [ ] האפליקציה נבדקה ב-Chrome על Android, ב-Safari על iOS, וב-Chrome ו-Safari על Desktop.
- [ ] ב-Anthropic Console רואים שהבקשות מה-Production נרשמות על מפתח ה-Production.
- [ ] `ANTHROPIC_API_KEY` לא חשוף: הוא לא מופיע בקוד הלקוח, ב-Repository או בתשובות API.
- [ ] המשתמש אישר שהמוצר מוכן.
